## 二、条件边(add_conditional_edges)

### 2.1 基本概念

条件边让你根据当前状态,动态选择下一个节点。三要素:
- **源节点**:从哪个节点出发。
- **路由函数**:接收 state,返回一个字符串(下一个节点的名字)或字符串列表(并行)。
- **映射字典**(可选):把路由函数返回值映射到节点名。

### 2.2 最简示例:情感路由

根据用户输入的情感,走"表扬"或"安慰"节点:

```python
"""Day3 条件边:情感路由"""
from typing import TypedDict
from langgraph.graph import StateGraph, START, END


class MoodState(TypedDict):
    user_input: str
    sentiment: str
    response: str


def detect_mood(state: MoodState) -> dict:
    text = state["user_input"].lower()
    if any(w in text for w in ["开心", "棒", "好", "great"]):
        return {"sentiment": "positive"}
    elif any(w in text for w in ["难过", "累", "糟", "bad"]):
        return {"sentiment": "negative"}
    return {"sentiment": "neutral"}


def praise(state: MoodState) -> dict:
    return {"response": "太棒了!继续保持!"}


def comfort(state: MoodState) -> dict:
    return {"response": "别难过,明天会更好。"}


def neutral(state: MoodState) -> dict:
    return {"response": "我听到你了。"}


def route_by_mood(state: MoodState) -> str:
    return state["sentiment"]


builder = StateGraph(MoodState)
builder.add_node("detect", detect_mood)
builder.add_node("praise", praise)
builder.add_node("comfort", comfort)
builder.add_node("neutral", neutral)

builder.add_edge(START, "detect")

# 条件边:从 detect 出发,由 route_by_mood 决定去哪
builder.add_conditional_edges(
    "detect",
    route_by_mood,
    {
        "positive": "praise",
        "negative": "comfort",
        "neutral": "neutral",
    },
)

# 三个终点节点都到 END
builder.add_edge("praise", END)
builder.add_edge("comfort", END)
builder.add_edge("neutral", END)

graph = builder.compile()

# 测试
for text in ["今天真开心", "我好难过", "今天星期一"]:
    result = graph.invoke({"user_input": text, "sentiment": "", "response": ""})
    print(f"输入:{text} → {result['response']}")
```

输出:
```
输入:今天真开心 → 太棒了!继续保持!
输入:我好难过 → 别难过,明天会更好。
输入:今天星期一 → 我听到你了。
```

### 2.3 路由函数返回值约定

- 返回字符串:走单个节点。
- 返回字符串列表(如 `["node_a", "node_b"]`):**并行**执行这些节点(下一节会用到)。
- 映射字典可省略:如果路由函数返回值正好等于节点名,可以不传第三个参数。
- 返回 `END`(字符串 `"__end__"` 或常量 `END`):直接结束。

## 三、Command 动态路由

### 3.1 Command 是什么

`Command` 是 LangGraph 0.2+ 引入的对象,让节点**在返回状态更新的同时,直接指定下一步去哪**。这比条件边更灵活,因为路由逻辑可以依赖节点内部计算的复杂结果。

```python
from langgraph.types import Command

def my_node(state):
    # 业务逻辑...
    return Command(
        update={"field": value},     # 状态更新
        goto="next_node",            # 下一个节点
    )
```

`Command` 的好处:
- 状态更新和路由决策放在一起,逻辑更内聚。
- 支持动态计算 goto,无需单独写路由函数。
- 支持 `goto` 为列表(并行)。

### 3.2 用 Command 改写情感路由

```python
"""Day3 用 Command 实现路由"""
from typing import TypedDict
from langgraph.graph import StateGraph, START, END
from langgraph.types import Command


class MoodState(TypedDict):
    user_input: str
    response: str


def detect_and_route(state: MoodState) -> Command:
    text = state["user_input"].lower()
    if any(w in text for w in ["开心", "棒"]):
        return Command(update={}, goto="praise")
    elif any(w in text for w in ["难过", "累"]):
        return Command(update={}, goto="comfort")
    return Command(update={}, goto="neutral")


def praise(state: MoodState) -> dict:
    return {"response": "太棒了!"}


def comfort(state: MoodState) -> dict:
    return {"response": "别难过。"}


def neutral(state: MoodState) -> dict:
    return {"response": "好的。"}


builder = StateGraph(MoodState)
builder.add_node("detect", detect_and_route)
builder.add_node("praise", praise)
builder.add_node("comfort", comfort)
builder.add_node("neutral", neutral)

builder.add_edge(START, "detect")
# 注意:使用 Command 时,detect 节点不需要显式 add_conditional_edges
# 但需要声明可能的去向(用 add_conditional_edges 占位或直接让 Command 处理)
# 实际上 Command 的 goto 会自动生效,无需额外声明边
builder.add_edge("praise", END)
builder.add_edge("comfort", END)
builder.add_edge("neutral", END)

graph = builder.compile()
result = graph.invoke({"user_input": "今天真开心", "response": ""})
print(result["response"])  # 太棒了!
```

> 注意:使用 `Command(goto=...)` 时,LangGraph 会自动识别去向。但为了图结构可静态分析(比如可视化),建议仍用 `add_conditional_edges` 声明可能路径,或在 `Command` 中使用 `goto` 指向已注册节点。

### 3.3 条件边 vs Command 怎么选

| 场景 | 推荐 |
|------|------|
| 路由逻辑简单,只看 state 字段 | 条件边 |
| 路由逻辑复杂,依赖节点内计算 | Command |
| 需要可视化清晰看到所有分支 | 条件边(映射字典显式) |
| 节点内部根据 LLM 输出决定去向 | Command |
| 多 Agent 编排(Day6) | Command(更灵活) |

两者可以混用。今天的 ReAct Agent 会用条件边,Day6 多 Agent 会大量用 Command。

## 四、循环图与递归限制

### 4.1 为什么需要循环

ReAct 模式本质是循环:
```
思考 → 行动(调工具) → 观察 → 思考 → 行动 → 观察 → ... → 最终回答
```

LangGraph 的图可以包含环(节点指向之前的节点),从而实现循环。

### 4.2 最简循环:计数器

```python
"""Day3 最简循环:数到 3 停"""
from typing import TypedDict
from langgraph.graph import StateGraph, START, END


class CountState(TypedDict):
    count: int


def increment(state: CountState) -> dict:
    return {"count": state["count"] + 1}


def should_continue(state: CountState) -> str:
    if state["count"] < 3:
        return "increment"  # 继续循环
    return END              # 结束


builder = StateGraph(CountState)
builder.add_node("increment", increment)
builder.add_edge(START, "increment")
builder.add_conditional_edges("increment", should_continue)

graph = builder.compile()
result = graph.invoke({"count": 0})
print(result["count"])  # 3
```

关键:`add_conditional_edges("increment", should_continue)` 没有传映射字典,因为 `should_continue` 返回值正好是节点名 `"increment"` 或 `END`。

### 4.3 recursion_limit(递归限制)

LangGraph 默认 `recursion_limit=25`,意思是图最多执行 25 个"超级步"(一个超级步是一轮节点执行)。如果循环不止,会抛 `RecursionError`。

- 调大:`graph.invoke(input, config={"recursion_limit": 50})`
- 调小:`config={"recursion_limit": 10}`

注意:这里的"递归"不是函数递归,而是图迭代的轮数。Agent 反复调工具时尤其要注意,避免死循环。

```python
# 危险示例:死循环
def bad_continue(state):
    return "increment"  # 永远不返回 END

# invoke 时会抛 RecursionError: Recursion limit of 25 reached
```

## 五、实战:ReAct 风格 Agent

ReAct = Reason + Act。Agent 先思考要不要用工具,用工具后观察结果,再思考,直到能直接回答。

我们用 LangGraph 从零搭建一个支持"计算器"和"天气查询(模拟)"两个工具的 ReAct Agent。

### 5.1 完整代码

```python
"""Day3 ReAct Agent:从零搭建带工具调用的循环图"""
import os
import json
from typing import TypedDict, Annotated
from dotenv import load_dotenv
from langchain_openai import ChatOpenAI
from langchain_core.messages import HumanMessage, AIMessage, ToolMessage
from langgraph.graph import StateGraph, START, END
from langgraph.graph.message import add_messages

load_dotenv()


# 1. 定义工具(LangChain Tool 格式)
def calculator(expression: str) -> str:
    """计算数学表达式,如 '2+3*4'"""
    try:
        # 注意:实际生产应使用安全的表达式求值,这里简化
        result = eval(expression, {"__builtins__": {}}, {})
        return f"计算结果:{expression} = {result}"
    except Exception as e:
        return f"计算失败:{type(e).__name__}: {e}"


def get_weather(city: str) -> str:
    """查询城市天气(模拟)"""
    fake_db = {"北京": "晴 25°C", "上海": "多云 28°C", "广州": "雨 30°C"}
    return fake_db.get(city, f"{city} 天气数据暂无")


# 2. 把工具绑定到 LLM
tools = [calculator, get_weather]
tools_by_name = {t.__name__: t for t in tools}

llm = ChatOpenAI(model="gpt-4o-mini", temperature=0)
llm_with_tools = llm.bind_tools(
    tools,
    # 让 LLM 知道工具的描述
)


# 3. 定义状态
class AgentState(TypedDict):
    messages: Annotated[list, add_messages]


# 4. Agent 节点:调用 LLM
def agent_node(state: AgentState) -> dict:
    response = llm_with_tools.invoke(state["messages"])
    return {"messages": [response]}


# 5. 工具执行节点:执行 LLM 要求调用的工具
def tool_node(state: AgentState) -> dict:
    last_msg: AIMessage = state["messages"][-1]
    tool_messages = []
    for call in last_msg.tool_calls:
        tool_name = call["name"]
        tool_args = call["args"]
        tool_id = call["id"]
        try:
            result = tools_by_name[tool_name](**tool_args)
        except (KeyError, TypeError, ValueError) as e:
            result = f"工具执行错误:{type(e).__name__}: {e}"
        tool_messages.append(
            ToolMessage(content=str(result), tool_call_id=tool_id)
        )
    return {"messages": tool_messages}


# 6. 路由:根据 LLM 是否要求调用工具决定下一步
def should_use_tool(state: AgentState) -> str:
    last_msg = state["messages"][-1]
    if hasattr(last_msg, "tool_calls") and last_msg.tool_calls:
        return "tools"
    return END


# 7. 构建图
def build_graph():
    builder = StateGraph(AgentState)
    builder.add_node("agent", agent_node)
    builder.add_node("tools", tool_node)

    builder.add_edge(START, "agent")
    builder.add_conditional_edges("agent", should_use_tool)
    builder.add_edge("tools", "agent")  # 工具执行完回到 agent,形成循环

    return builder.compile()


# 8. 运行
def main():
    graph = build_graph()

    questions = [
        "北京和上海今天天气怎么样?然后告诉我这两个城市温度差。",
    ]

    for q in questions:
        print(f"\n用户:{q}")
        state = {"messages": [HumanMessage(content=q)]}
        # 工具可能多次调用,适当调大递归限制
        result = graph.invoke(
            state,
            config={"recursion_limit": 15},
        )
        final_msg = result["messages"][-1]
        print(f"AI:{final_msg.content}")
        print(f"(共 {len(result['messages'])} 条消息)")


if __name__ == "__main__":
    main()
```

### 5.2 运行流程解析

以"北京和上海今天天气怎么样?然后告诉我温度差"为例:

1. `agent` 节点:LLM 决定同时调用 `get_weather(北京)` 和 `get_weather(上海)`(两次 tool_calls)。
2. `should_use_tool` 返回 `"tools"`,进入 `tools` 节点。
3. `tools` 节点:执行两个工具,返回两个 `ToolMessage`(天气数据)。
4. 边 `tools → agent`:回到 `agent` 节点。
5. `agent` 节点:LLM 看到天气数据,决定调用 `calculator` 算温差。
6. `should_use_tool` 返回 `"tools"`,进入 `tools`。
7. `tools` 执行 `calculator`,返回结果。
8. `tools → agent`:回到 `agent`。
9. `agent`:LLM 综合所有信息,生成最终自然语言回答,无 tool_calls。
10. `should_use_tool` 返回 `END`,结束。

这就是 ReAct 循环:每次 LLM 调工具 → 执行 → 回到 LLM,直到 LLM 不再要工具。

### 5.3 预期输出(示意)

```
用户:北京和上海今天天气怎么样?然后告诉我这两个城市温度差。
AI:北京今天晴 25°C,上海多云 28°C,两个城市温度差为 3°C。
(共 7 条消息)
```

7 条消息构成:1 Human + 1 AI(tool_calls) + 2 Tool + 1 AI(tool_calls) + 1 Tool + 1 AI(最终)。

## 六、动态并行(进阶)

条件边的路由函数如果返回**列表**,会并行执行多个节点:

```python
def fan_out(state) -> list:
    return ["worker_a", "worker_b", "worker_c"]

builder.add_conditional_edges("dispatcher", fan_out)
```

三个 worker 会并行执行,它们的状态更新在汇合后合并(通过各自的 Reducer)。这在 Day6 多 Agent 编排中非常有用。

---

## 七、当日小结

- **条件边** `add_conditional_edges(源, 路由函数, 映射字典)`:根据 state 路由,返回字符串走单节点,返回列表并行多节点。
- **Command** `Command(update=..., goto=...)`:在节点内部同时更新状态和指定去向,适合复杂路由。
- **循环**:节点可以指回之前的节点形成环,实现 ReAct 等迭代模式。
- **recursion_limit**:默认 25,通过 `config={"recursion_limit": N}` 调整,防止死循环。
- **ReAct 模式**:`agent →(有 tool_calls)→ tools → agent → ... →(无 tool_calls)→ END`。

## 九、练习题答案

### 1. 答案:B
解析:返回列表会**并行**执行列表中的所有节点,这是 LangGraph 的 fan-out 机制。并行节点的状态更新在所有完成后通过 Reducer 合并。

### 2. 答案:B
解析:`recursion_limit` 限制的是图的"超级步"数(一轮节点执行算一个超级步),不是函数调用栈。默认 25。可在 `invoke`/`stream` 的 `config` 中设置,也能在 `compile` 时通过 `recursion_limit` 参数设置。设为 0 不会变成无限,会立即报错。

### 3. 答案:B
解析:`goto` 必须指向已注册的节点名(或 `END`)。使用 Command 时不需要再显式 `add_conditional_edges`,LangGraph 会自动处理。Command 完全支持循环图。

### 4. 答案:`END`
解析:从 `langgraph.graph` 导入的 `END` 常量,路由函数返回它即结束。也可返回字符串 `"__end__"`。

### 5. 答案:`agent`(或你给 Agent 节点起的名字)
解析:ReAct 循环的关键是工具执行后回到 Agent,让 LLM 看到工具结果再决定下一步。

### 6. 答案:`langgraph.types`
解析:`from langgraph.types import Command`。Day5 还会从这里导入 `interrupt`。

### 7. 参考代码

```python
"""Day3 练习题7:数字猜想循环图"""
from typing import TypedDict
from langgraph.graph import StateGraph, START, END


class GuessState(TypedDict):
    number: int
    rounds: int


def guess(state: GuessState) -> dict:
    return {"number": state["number"] + 7, "rounds": state["rounds"] + 1}


def check(state: GuessState) -> str:
    if state["number"] >= 100:
        return END
    return "guess"


builder = StateGraph(GuessState)
builder.add_node("guess", guess)
builder.add_edge(START, "guess")
builder.add_conditional_edges("guess", check)

graph = builder.compile()
result = graph.invoke({"number": 0, "rounds": 0})
print(f"最终数字:{result['number']},迭代轮数:{result['rounds']}")
# 0 →7→14→...→98→105,105>=100 停,rounds=15
assert result["number"] >= 100
assert result["rounds"] == 15
```

```python
"""Day3 练习题8:扩展 ReAct Agent,新增 word_count 工具"""
import os
from typing import TypedDict, Annotated
from dotenv import load_dotenv
from langchain_openai import ChatOpenAI
from langchain_core.messages import HumanMessage, AIMessage, ToolMessage
from langgraph.graph import StateGraph, START, END
from langgraph.graph.message import add_messages

load_dotenv()


def calculator(expression: str) -> str:
    """计算数学表达式"""
    try:
        result = eval(expression, {"__builtins__": {}}, {})
        return f"{expression} = {result}"
    except (SyntaxError, NameError, TypeError, ZeroDivisionError) as e:
        return f"计算失败:{type(e).__name__}"


def get_weather(city: str) -> str:
    """查询天气(模拟)"""
    return {"北京": "晴 25°C", "上海": "多云 28°C"}.get(city, "无数据")


def word_count(text: str) -> str:
    """统计字符串单词数(按空格分)"""
    count = len(text.split())
    return f"'{text}' 有 {count} 个单词"


tools = [calculator, get_weather, word_count]
tools_by_name = {t.__name__: t for t in tools}

llm = ChatOpenAI(model="gpt-4o-mini", temperature=0)
llm_with_tools = llm.bind_tools(tools)


class AgentState(TypedDict):
    messages: Annotated[list, add_messages]


def agent_node(state: AgentState) -> dict:
    return {"messages": [llm_with_tools.invoke(state["messages"])]}


def tool_node(state: AgentState) -> dict:
    last_msg: AIMessage = state["messages"][-1]
    out = []
    for call in last_msg.tool_calls:
        try:
            r = tools_by_name[call["name"]](**call["args"])
        except (KeyError, TypeError, ValueError) as e:
            r = f"工具错误:{type(e).__name__}"
        out.append(ToolMessage(content=str(r), tool_call_id=call["id"]))
    return {"messages": out}


def should_use_tool(state: AgentState) -> str:
    last = state["messages"][-1]
    if hasattr(last, "tool_calls") and last.tool_calls:
        return "tools"
    return END


builder = StateGraph(AgentState)
builder.add_node("agent", agent_node)
builder.add_node("tools", tool_node)
builder.add_edge(START, "agent")
builder.add_conditional_edges("agent", should_use_tool)
builder.add_edge("tools", "agent")
graph = builder.compile()

result = graph.invoke(
    {"messages": [HumanMessage(content="计算 (12+8)*3,并告诉我 'hello langgraph world' 有几个单词")]},
    config={"recursion_limit": 15},
)
print("最终回答:", result["messages"][-1].content)
print("消息总数:", len(result["messages"]))
# Agent 应能串联调用 calculator 和 word_count,最终给出综合回答
```
