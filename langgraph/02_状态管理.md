## 二、State 的两种定义方式

### 2.1 TypedDict 方式(推荐入门)

`TypedDict` 是 Python 类型系统提供的工具,用于定义一个字典的键和值类型。LangGraph 最常使用它:

```python
from typing import TypedDict, Annotated
from langgraph.graph.message import add_messages

class ChatState(TypedDict):
    messages: Annotated[list, add_messages]
    user_id: str
    turn_count: int
```

优点:
- 语法简洁,接近普通字典。
- 运行时零开销(只是类型提示)。
- 与 LangGraph 内置 Reducer(`add_messages`)配合自然。

注意:`TypedDict` 本身不做运行时校验。如果你传了错误类型的值,运行时不会报错,但可能在后续节点里出错。

### 2.2 Pydantic BaseModel 方式(推荐生产)

`Pydantic` 提供运行时数据校验,适合对数据完整性要求高的场景:

```python
from pydantic import BaseModel, Field
from typing import Annotated
from langgraph.graph.message import add_messages

class ChatState(BaseModel):
    messages: Annotated[list, add_messages] = Field(default_factory=list)
    user_id: str = ""
    turn_count: int = 0
```

优点:
- 运行时校验类型、约束字段(如 `Field(ge=0)` 限制非负)。
- 自动生成 JSON Schema,便于文档化和前端对接。
- 错误信息更友好。

注意:使用 Pydantic 时,节点函数返回的字典同样只包含要更新的字段。LangGraph 会做合并。

### 2.3 如何选择

| 场景 | 推荐 |
|------|------|
| 快速原型、学习 Demo | TypedDict |
| 生产应用、需要严格校验 | Pydantic |
| 与外部 API 交互、需要 Schema | Pydantic |
| 简单内部工作流 | TypedDict |

## 三、Reducer 机制详解

### 3.1 为什么需要 Reducer

假设有两个节点 A 和 B,都返回 `{"messages": [新消息]}`。如果没有 Reducer,B 的返回会**覆盖** A 的结果,messages 只剩 B 的那条。这显然不是我们想要的——我们希望消息**累积**。

Reducer 就是用来自定义"如何合并新旧值"的函数。签名:

```python
def reducer(old_value, new_value) -> combined_value:
    ...
```

通过 `Annotated[类型, reducer函数]` 绑定到字段上。

### 3.2 默认行为:覆盖

没有 Reducer 的字段,默认就是"新值覆盖旧值":

```python
class State(TypedDict):
    count: int  # 无 Reducer,默认覆盖

# 节点 A 返回 {"count": 1},节点 B 返回 {"count": 2}
# 最终 count == 2
```

### 3.3 内置 Reducer:add_messages

`add_messages` 是 LangGraph 提供的最常用 Reducer,用于消息列表的追加,并支持**按 id 去重更新**:

```python
from typing import Annotated
from langgraph.graph.message import add_messages

class State(TypedDict):
    messages: Annotated[list, add_messages]
```

行为:
- 如果新消息没有 `id`,直接追加到列表末尾。
- 如果新消息有 `id` 且与已有消息 `id` 相同,则**替换**那条旧消息(用于编辑/更新消息)。
- 否则追加。

示例:

```python
from langchain_core.messages import AIMessage, HumanMessage

# 追加
new_messages = [HumanMessage(content="你好", id="1")]
# 假设原 messages 为 [],合并后:[HumanMessage(content="你好", id="1")]

# 按 id 更新
update = [AIMessage(content="你好,我是 AI", id="1")]
# 如果原 messages 里已有 id="1" 的消息,会被替换
```

### 3.4 内置 Reducer:add_operator(累加)

如果你想要一个整数计数器不断累加:

```python
from typing import Annotated
from operator import add

class State(TypedDict):
    turn_count: Annotated[int, add]

# 节点 A 返回 {"turn_count": 1}
# 节点 B 返回 {"turn_count": 1}
# 最终 turn_count == 2(1 + 1)
```

`operator.add` 对整数是加法,对列表是拼接,对字符串是连接,行为取决于类型。

### 3.5 自定义 Reducer

你可以写自己的合并函数。比如"保留最大的那个数":

```python
from typing import Annotated

def keep_max(old: int, new: int) -> int:
    return max(old if old is not None else 0, new if new is not None else 0)

class State(TypedDict):
    max_score: Annotated[int, keep_max]
```

再比如"合并两个字典":

```python
from typing import Annotated

def merge_dict(old: dict, new: dict) -> dict:
    merged = dict(old or {})
    merged.update(new or {})
    return merged

class State(TypedDict):
    metadata: Annotated[dict, merge_dict]
```

自定义 Reducer 的关键:第一个参数是旧值(可能为 `None`,首次更新时),第二个是新值,返回合并后的值。

## 四、多节点更新同一字段实战

我们构建一个图,展示三种字段的不同合并行为:
- `messages`:追加(`add_messages`)。
- `turn_count`:累加(`operator.add`)。
- `last_topic`:覆盖(默认)。

### 4.1 完整代码

```python
"""Day2 多节点状态合并示例"""
import operator
from typing import TypedDict, Annotated
from langchain_core.messages import AIMessage, HumanMessage
from langgraph.graph import StateGraph, START, END
from langgraph.graph.message import add_messages


class ConversationState(TypedDict):
    messages: Annotated[list, add_messages]
    turn_count: Annotated[int, operator.add]
    last_topic: str  # 默认覆盖


def user_node(state: ConversationState) -> dict:
    """模拟用户输入"""
    return {
        "messages": [HumanMessage(content="今天天气怎么样?", id="u1")],
        "turn_count": 1,
        "last_topic": "天气",
    }


def ai_node(state: ConversationState) -> dict:
    """模拟 AI 回复(不调用真实 LLM,便于离线运行)"""
    return {
        "messages": [AIMessage(content="今天晴天,适合出门。", id="a1")],
        "turn_count": 1,
        "last_topic": "天气",
    }


def followup_node(state: ConversationState) -> dict:
    """追问节点"""
    return {
        "messages": [HumanMessage(content="那明天呢?", id="u2")],
        "turn_count": 1,
        "last_topic": "明天天气",
    }


def build_graph():
    builder = StateGraph(ConversationState)
    builder.add_node("user", user_node)
    builder.add_node("ai", ai_node)
    builder.add_node("followup", followup_node)

    builder.add_edge(START, "user")
    builder.add_edge("user", "ai")
    builder.add_edge("ai", "followup")
    builder.add_edge("followup", END)
    return builder.compile()


def main():
    graph = build_graph()
    initial_state: ConversationState = {
        "messages": [],
        "turn_count": 0,
        "last_topic": "",
    }
    result = graph.invoke(initial_state)
    print("=== 最终状态 ===")
    print(f"turn_count(累加):{result['turn_count']}")  # 期望 3
    print(f"last_topic(覆盖):{result['last_topic']}")  # 期望 "明天天气"
    print(f"messages 条数(追加):{len(result['messages'])}")  # 期望 3
    for msg in result["messages"]:
        print(f"  [{msg.type}] {msg.content}")


if __name__ == "__main__":
    main()
```

### 4.2 预期输出

```
=== 最终状态 ===
turn_count(累加):3
last_topic(覆盖):明天天气
messages 条数(追加):3
  [human] 今天天气怎么样?
  [ai] 今天晴天,适合出门。
  [human] 那明天呢?
```

注意:
- `turn_count` 三个节点各返回 1,累加结果 3。
- `last_topic` 最后被 `followup` 节点覆盖为"明天天气"。
- `messages` 三条消息全部保留,顺序正确。

## 五、用 Pydantic 定义状态(进阶)

把上面的例子改成 Pydantic 版本,加上字段校验:

```python
"""Day2 Pydantic State 示例"""
import operator
from typing import Annotated
from pydantic import BaseModel, Field
from langchain_core.messages import AIMessage, HumanMessage
from langgraph.graph import StateGraph, START, END
from langgraph.graph.message import add_messages


class ConversationState(BaseModel):
    messages: Annotated[list, add_messages] = Field(default_factory=list)
    turn_count: Annotated[int, operator.add] = Field(default=0, ge=0)
    last_topic: str = ""


def user_node(state: ConversationState) -> dict:
    return {
        "messages": [HumanMessage(content="讲个笑话", id="u1")],
        "turn_count": 1,
        "last_topic": "笑话",
    }


def ai_node(state: ConversationState) -> dict:
    return {
        "messages": [AIMessage(content="为什么程序员喜欢黑色?因为 bug 在黑里看不见。", id="a1")],
        "turn_count": 1,
        "last_topic": "笑话",
    }


builder = StateGraph(ConversationState)
builder.add_node("user", user_node)
builder.add_node("ai", ai_node)
builder.add_edge(START, "user")
builder.add_edge("user", "ai")
builder.add_edge("ai", END)

graph = builder.compile()
result = graph.invoke(ConversationState())
print(f"turn_count: {result['turn_count']}")  # 2
print(f"messages: {len(result['messages'])} 条")  # 2
```

Pydantic 版本会在传入非法值时抛出 `ValidationError`,例如 `turn_count=-1` 会被 `ge=0` 拦截。

## 六、实战:带消息历史的对话 Agent

我们把 Day1 的示例升级成一个真正的多轮对话 Agent。它接收用户消息,调用 LLM 回复,并把完整历史维护在 state 中。

### 6.1 完整代码

```python
"""Day2 带消息历史的对话 Agent"""
import os
from typing import TypedDict, Annotated
from dotenv import load_dotenv
from langchain_openai import ChatOpenAI
from langchain_core.messages import HumanMessage, SystemMessage
from langgraph.graph import StateGraph, START, END
from langgraph.graph.message import add_messages

load_dotenv()


class AgentState(TypedDict):
    messages: Annotated[list, add_messages]


def chat_node(state: AgentState) -> dict:
    llm = ChatOpenAI(model="gpt-4o-mini", temperature=0.7)
    system = SystemMessage(content="你是一个友好的中文助手,回答简洁。")
    response = llm.invoke([system] + state["messages"])
    return {"messages": [response]}


def build_graph():
    builder = StateGraph(AgentState)
    builder.add_node("chat", chat_node)
    builder.add_edge(START, "chat")
    builder.add_edge("chat", END)
    return builder.compile()


def main():
    graph = build_graph()

    # 第一轮
    state = {"messages": [HumanMessage(content="我叫小明,请记住我的名字。")]}
    state = graph.invoke(state)
    print("AI:", state["messages"][-1].content)

    # 第二轮:用上一轮的 messages 作为输入,验证历史保留
    state["messages"].append(HumanMessage(content="我刚才告诉你我叫什么?"))
    state = graph.invoke(state)
    print("AI:", state["messages"][-1].content)

    print(f"\n总消息数:{len(state['messages'])}")


if __name__ == "__main__":
    main()
```

### 6.2 关键点

- 第二轮调用 `graph.invoke` 时,把第一轮返回的 `messages` 全部传入,LLM 能看到完整历史。
- `[system] + state["messages"]` 中,`system` 不写入 state(只作为 LLM 输入),`state["messages"]` 中的内容会被 LLM 看到。
- `chat_node` 返回的 `response` 通过 `add_messages` 追加到历史。

> 注意:这里的多轮是"手动"维护的。Day4 学了 Checkpointer 后,可以由框架自动管理线程记忆,无需手动传 messages。

## 七、State 设计最佳实践

1. **字段最小化**:只放图流转真正需要的字段,不要把所有临时变量都塞进 state。节点内部的局部变量就放在节点里。
2. **明确 Reducer**:对需要累积的字段(消息、计数器、日志)显式声明 Reducer,避免默认覆盖导致的 bug。
3. **不可变意识**:节点返回增量字典,不要直接修改传入的 state 对象(虽然技术上可以,但会让状态流转难以追踪)。
4. **类型一致**:同一个字段在所有节点中返回的类型要一致,否则 Reducer 可能出错。
5. **消息用 id**:给消息加 `id` 可以支持后续的更新/删除(Day5 人机协同会用到)。

## 八、当日小结

- State 用 `TypedDict`(轻量)或 `Pydantic`(带校验)定义。
- Reducer 决定字段如何合并:
  - 无 Reducer = 覆盖。
  - `add_messages` = 消息追加(支持按 id 更新)。
  - `operator.add` = 累加/拼接。
  - 自定义函数 = 任意合并逻辑。
- 通过 `Annotated[类型, reducer]` 绑定 Reducer。
- 节点返回增量字典,LangGraph 负责合并。
- 多轮对话的核心是 `messages` 字段的累积,LLM 通过看到完整历史实现"记忆"。

## 十、练习题答案

### 1. 答案:D
解析:Reducer 可以是任意自定义函数,不限于 LangGraph 内置。`operator.add`、自己写的 `keep_max` 等都可以作为 Reducer。

### 2. 答案:C
解析:`add_messages` 的去重逻辑:相同 id 的消息会被新消息替换。这正是"编辑消息"的实现方式。没有 id 的消息则直接追加。

### 3. 答案:B
解析:Pydantic 的核心价值是运行时校验(`ValidationError`)和字段约束(`Field(ge=0)` 等)。TypedDict 只是静态类型提示,运行时不校验。

### 4. 答案:`operator.add`
解析:`from operator import add` 或 `import operator; Annotated[int, operator.add]`。`add` 对整数是 `+`,对列表是 `+`(拼接)。

### 5. 答案:需要更新(增量)
解析:节点返回增量字典,LangGraph 用 Reducer 合并到当前状态。返回全量状态会导致 Reducer 误操作(比如 `add_messages` 会把全部历史再追加一遍)。

### 6. 答案:`langgraph.graph.message`
解析:`from langgraph.graph.message import add_messages`。

### 7. 参考代码

```python
"""Day2 练习题7:logs 累加 + status 覆盖"""
import operator
from typing import TypedDict, Annotated
from langgraph.graph import StateGraph, START, END


class TaskState(TypedDict):
    logs: Annotated[list, operator.add]
    status: str


def step1(state: TaskState) -> dict:
    return {"logs": ["step1 开始"], "status": "running"}


def step2(state: TaskState) -> dict:
    return {"logs": ["step2 处理中"], "status": "running"}


def step3(state: TaskState) -> dict:
    return {"logs": ["step3 完成"], "status": "done"}


builder = StateGraph(TaskState)
builder.add_node("step1", step1)
builder.add_node("step2", step2)
builder.add_node("step3", step3)
builder.add_edge(START, "step1")
builder.add_edge("step1", "step2")
builder.add_edge("step2", "step3")
builder.add_edge("step3", END)

graph = builder.compile()
result = graph.invoke({"logs": [], "status": "init"})
print("logs:", result["logs"])        # 3 条
print("status:", result["status"])    # done
assert len(result["logs"]) == 3
assert result["status"] == "done"
```

### 8. 参考代码

```python
"""Day2 练习题8:自定义 keep_longest Reducer"""
from typing import TypedDict, Annotated
from langgraph.graph import StateGraph, START, END


def keep_longest(old: str, new: str) -> str:
    old = old or ""
    new = new or ""
    return new if len(new) >= len(old) else old


class SummaryState(TypedDict):
    summary: Annotated[str, keep_longest]


def short_node(state: SummaryState) -> dict:
    return {"summary": "短"}


def long_node(state: SummaryState) -> dict:
    return {"summary": "这是一个比较长的摘要内容"}


builder = StateGraph(SummaryState)
builder.add_node("short", short_node)
builder.add_node("long", long_node)
builder.add_edge(START, "short")
builder.add_edge("short", "long")
builder.add_edge("long", END)

graph = builder.compile()
result = graph.invoke({"summary": ""})
print("最终 summary:", result["summary"])
assert result["summary"] == "这是一个比较长的摘要内容"

# 反过来:long 在前 short 在后,仍应保留长的
builder2 = StateGraph(SummaryState)
builder2.add_node("long", long_node)
builder2.add_node("short", short_node)
builder2.add_edge(START, "long")
builder2.add_edge("long", "short")
builder2.add_edge("short", END)
graph2 = builder2.compile()
result2 = graph2.invoke({"summary": ""})
print("反序 summary:", result2["summary"])
assert result2["summary"] == "这是一个比较长的摘要内容"
```
