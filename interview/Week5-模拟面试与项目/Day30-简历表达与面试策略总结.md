### Q1: AI Agent 岗位简历怎么写? 项目描述用什么模板? 如何做关键词优化? 有哪些常见错误?

<details>
<summary>查看答案</summary>

#### 一、项目描述模板:STAR + 量化

AI Agent 岗位的简历项目,核心是用 **STAR + 量化** 结构,让面试官 30 秒内看懂"你做了什么 + 达成了什么"。

**标准模板:**

```
[项目名] | [你的角色] | [时间]
背景(S): 一句话业务背景 + 痛点
任务(T): 你负责的目标
行动(A): 技术方案(关键选型 + 架构 + 你做的核心模块)
结果(R): 量化指标(至少 2 个,业务 + 技术各 1)
```

**示例 1(企业级 RAG Agent):**

> **智能客服 RAG Agent 系统** | 核心开发 | 2025.03-2025.09
>
> **S**: 公司客服系统日均 50w 会话,传统 FAQ 召回准确率仅 62%,人工转接率 35%。
> **T**: 负责设计基于 LLM + RAG 的智能客服 Agent,目标将一次解决率从 62% 提升至 80%+。
> **A**:
> - 设计多路召回架构(BM25 + Embedding + Rerank),召回准确率从 62% 提升至 89%
> - 实现 Function Calling 工具调用模块,支持订单查询、退款、工单创建等 12 个工具
> - 引入 ReAct 推理框架,处理多轮对话中的意图跳转,平均轮次从 5.2 降至 3.1
> - 使用 vLLM 部署 Qwen2.5-72B,P99 延迟从 3.2s 降至 1.1s,单卡 QPS 从 2 提升至 18
>
> **R**: 一次解决率提升至 84%(+22pp),人工转接率降至 18%(-17pp),年节省人力成本约 1200w。

**示例 2(多 Agent 协作系统):**

> **代码生成 Multi-Agent 平台** | 技术负责人 | 2024.10-2025.06
>
> **S**: 内部研发效率低,CR 平均周期 3 天,重复性代码占比 40%。
> **T**: 设计多 Agent 协作平台,自动生成 PR 并通过 CR。
> **A**:
> - 设计 Planner-Executor-Critic 三角色架构,Planner 拆解任务,Executor 调用代码生成,Reviewer 校验
> - 实现 Agent 间消息总线,基于 Redis Stream,支持 50+ Agent 并发
> - 构建 Sandbox 代码执行环境,基于 Firecracker microVM,隔离性 + 秒级启动
> - 设计 Memory 模块,长期记忆存向量库,短期记忆用滑动窗口,上下文压缩比 5:1
>
> **R**: 自动生成 PR 合并率 73%,CR 周期从 3 天降至 0.8 天,研发效率提升约 35%。

#### 二、关键词优化(ATS 友好)

很多大厂用 ATS(Applicant Tracking System)做简历初筛,关键词命中率高才能过初筛。

| 类别 | 关键词 |
|------|--------|
| 模型 | LLM / GPT / Claude / Qwen / Llama / 指令微调 / SFT / RLHF |
| Agent 核心 | Agent / Multi-Agent / ReAct / Planner / Memory / Tool Use / Function Calling |
| RAG | RAG / Embedding / 向量数据库 / Milvus / Pinecone / Rerank / Hybrid Search |
| 框架 | LangChain / LlamaIndex / AutoGen / CrewAI / LangGraph |
| 推理优化 | vLLM / TensorRT-LLM / KV Cache / PagedAttention / 量化 / 蒸馏 |
| 工程 | Python / FastAPI / Ray / Redis / Kafka / Docker / K8s |
| 评估 | 评估集 / 离线指标 / A/B 测试 / 人工标注 |

**技巧:**
- 关键词必须出现在项目描述里,不能只在"技能"栏堆砌
- 用 JD 里的原词(如 JD 写"大模型"你就别只写"LLM")
- 每个项目至少覆盖 3-5 个核心关键词

#### 三、常见错误

| 错误类型 | 错误示例 | 改进写法 |
|---------|---------|---------|
| 只写做了什么不写结果 | "负责 RAG 系统开发" | "设计 RAG 召回架构,准确率从 62% 提升至 89%" |
| 堆砌名词无细节 | "使用 LangChain 开发 Agent" | "基于 LangGraph 实现状态机式 Agent,支持 12 个工具调用,平均轮次从 5.2 降至 3.1" |
| 量化虚假 | "大幅提升效率" | "CR 周期从 3 天降至 0.8 天" |
| 项目与 JD 不匹配 | 投 Agent 岗但全是 CRUD | 把后端项目改写为"为 Agent 提供工具层支持" |
| 简历过长 | 5 页纸 | 控制在 2 页内,应届生 1 页 |
| 技术栈罗列 | "熟悉 Python/Java/Go/C++" | 只写与岗位相关的,深度优先 |
| 没有亮点项目 | 10 个项目都平淡 | 突出 2-3 个深度项目,其余一句话带过 |
| 拼写/格式错误 | "Langchian" | 仔细校对,PDF 导出后再看一遍 |

#### 四、简历结构建议(1-2 页)

```
1. 个人信息 (姓名 / 联系方式 / GitHub / 博客)
2. 教育背景 (一行,学校 + 专业 + 学历)
3. 工作经历 (公司 + 岗位 + 时间 + 2-3 个项目)
4. 技术技能 (分类罗列,不堆砌)
5. 开源贡献 / 论文 / 专利 (有则写,无则省)
6. 个人项目 / 比赛 (转 Agent 岗尤其重要)
```

### Q2: 简历中的 Agent 项目如何量化? 如果没有线上数据怎么办?

<details>
<summary>查看答案</summary>

#### 一、为什么量化重要

面试官看简历时,大脑会自动做两个判断:
1. **真实性判断**:有数字 = 真做过,没数字 = 可能编的
2. **能力判断**:数字的大小 = 你的水平高低

所以即使项目不大,也要尽力量化。

#### 二、量化的三个层次

| 层次 | 类型 | 示例 |
|------|------|------|
| L1 | 业务指标 | 一次解决率 +22pp、转化率 +15%、人力成本 -1200w |
| L2 | 技术指标 | P99 延迟 3.2s→1.1s、QPS 2→18、召回准确率 62%→89% |
| L3 | 工程指标 | 代码量 5w 行、服务 50+ Agent 并发、SLA 99.9% |

**理想状态:每个项目至少有 L1 + L2 各一个。**

#### 三、没有线上数据怎么办?

这是转 Agent 岗同学最常见的问题。三种解决方案:

##### 方案 1:离线评估(最常用)

搭建评估集,跑对比实验,给出离线指标。

```
示例:
"构建 500 条客服 QA 评估集,对比基线(BM25)与 RAG 方案:
- 召回准确率: BM25 62% → RAG 89% (+27pp)
- 答案相关性(人工评分 1-5): 3.1 → 4.3
- 幻觉率(人工标注): 18% → 4%"
```

##### 方案 2:对比实验

与 baseline / 上一版本对比,即使没有线上 AB,离线对比也有说服力。

```
示例:
"对比 GPT-3.5 vs Qwen2.5-72B 在内部代码生成任务:
- 功能正确率(pass@1): 71% vs 78%
- 平均 token 成本: $0.012 vs $0.003 (-75%)
- 中文注释生成质量(人工 1-5): 3.8 vs 4.2"
```

##### 方案 3:技术指标 + 规模指标

没有效果数据,就写规模和性能。

```
示例:
"设计 Multi-Agent 消息总线:
- 支持 50+ Agent 并发,消息吞吐 10k TPS
- P99 延迟 < 50ms
- 基于 Redis Stream,持久化 + 重放
- 代码量约 8000 行,单元测试覆盖率 85%"
```

#### 四、量化数字的"合理区间"参考

| 指标 | 合理范围 | 不合理(疑似编造) |
|------|---------|------------------|
| RAG 召回准确率提升 | +10pp ~ +30pp | +50pp |
| 延迟优化 | 降低 30% ~ 70% | 降低 95% |
| 成本节省 | 10% ~ 50% | 90% |
| QPS 提升 | 2x ~ 10x | 100x |
| 人力成本节省 | 几百万 ~ 几千万 | 上亿 |

**面试官心里有数,数字太离谱反而扣分。**

#### 五、量化的"诚实原则"

- **不要编造**:面试官会追问数字怎么来的,编不出来就崩了
- **可以说"估算"**:"估算年节省人力成本约 1200w,基于日均 50w 会话 × 转接率降低 17pp × 单次人工成本 8 元 × 365 天"
- **可以说"部分贡献"**:"作为核心开发,负责召回模块,准确率提升 27pp 中约 15pp 来自我负责的模块"
- **可以说"未上线"**:"项目处于 POC 阶段,以下为离线评估结果"

#### 六、量化模板速查

```
[动作动词] + [技术方案] + [量化指标] + [对比基线]

例:
设计多路召回架构(BM25+Embedding+Rerank),召回准确率从 62% 提升至 89%(+27pp)
实现 KV Cache 复用,P99 延迟从 3.2s 降至 1.1s(-66%)
引入 Agent Memory 模块,上下文压缩比 5:1,token 成本降低 80%
```

### Q3: 从非 Agent 岗位转 Agent,简历如何包装? 迁移经验、补充项目、开源贡献怎么做?

<details>
<summary>查看答案</summary>

#### 一、转岗的核心矛盾

面试官的担忧:
1. 你没做过真正的 Agent 项目,能力存疑
2. 你的经验能否迁移到 Agent 方向
3. 你是不是"追热点"刷简历

**简历包装的核心:证明你的经验可迁移 + 你已经主动做了 Agent 项目。**

#### 二、迁移经验:把现有经验"翻译"成 Agent 语言

##### 案例 1:后端开发 → Agent 方向

| 原经验 | 迁移包装 |
|--------|---------|
| 设计微服务架构 | "设计高并发服务架构,经验可直接迁移到 Agent 服务编排" |
| 实现 API 网关 | "设计 API 网关与鉴权,经验适用于 Function Calling 工具层" |
| 优化数据库查询 | "向量数据库选型与查询优化经验" |
| 消息队列 Kafka | "Agent 间异步通信与事件驱动架构经验" |

##### 案例 2:算法工程师(推荐/NLP) → Agent 方向

| 原经验 | 迁移包装 |
|--------|---------|
| 推荐系统召回排序 | "召回-排序经验直接适用于 RAG 多路召回与 Rerank" |
| NLP 文本分类 | "Prompt Engineering 与意图理解经验" |
| 模型部署 Triton | "LLM 推理优化经验(vLLM/TensorRT-LLM)" |
| A/B 实验平台 | "Agent 效果评估与 A/B 实验设计经验" |

##### 案例 3:前端/客户端 → Agent 方向

| 原经验 | 迁移包装 |
|--------|---------|
| 复杂状态管理 | "Agent 状态机与对话流管理经验" |
| 流式渲染 | "LLM 流式输出与 SSE 经验" |
| 可视化编排 | "Agent Workflow 可视化编排经验" |

#### 三、补充项目:自驱做 Agent 项目

转岗必须有 1-2 个"自驱 Agent 项目"放在简历显眼位置。三种来源:

##### 1. 复现开源项目 + 改进

```
示例项目:
"基于 AutoGen 复现多 Agent 代码评审系统,并改进:
- 原版支持单文件评审,扩展为多文件 + 跨文件依赖分析
- 增加 Reviewer Agent 的 Rubric 评分机制
- 在 HumanEval 数据集上 pass@1 从 68% 提升至 74%
GitHub: github.com/xxx/multi-agent-reviewer (star 120+)"
```

##### 2. 解决真实痛点的小工具

```
示例项目:
"个人知识库 Agent:
- 接入 Obsidian 5000+ 笔记,基于 RAG 实现智能问答
- 支持 Function Calling 调用日历、待办、邮件
- 部署在本地 Mac,日均调用 50+ 次
- 技术栈: LangChain + Chroma + Qwen2.5-7B + Ollama"
```

##### 3. 参加 Agent 比赛

```
示例项目:
"2025 AgentBench 国际评测赛 Top 10:
- 设计任务规划 Agent,在 50+ 复杂任务上完成率 78%
- 贡献了 Tool Selection 模块的设计
- 团队 3 人,我负责 Agent 核心逻辑"
```

#### 四、开源贡献:刷存在感

| 方式 | 难度 | 简历加分 |
|------|------|---------|
| 给 LangChain/LlamaIndex 提 PR | 中 | ⭐⭐⭐⭐⭐ |
| 维护一个 Agent 相关小工具 | 中 | ⭐⭐⭐⭐ |
| 写 Agent 技术博客(知乎/掘金) | 低 | ⭐⭐⭐ |
| 在开源 Agent 项目里回答 issue | 低 | ⭐⭐ |
| 复现论文并开源 | 高 | ⭐⭐⭐⭐⭐ |

**示例简历写法:**

```
开源贡献:
- LangChain Contributor,合并 3 个 PR(新增 2 个 Tool,修复 Memory bug)
- 个人项目 agent-eval(Agent 评估框架)GitHub star 280+
- 知乎专栏"Agent 技术笔记",累计阅读 10w+,粉丝 2k
```

#### 五、转岗简历的"诚实底线"

可以做:
- 把后端经验"翻译"成 Agent 语言
- 突出可迁移能力
- 强调自驱学习与项目

不能做:
- 把团队项目说成自己独立完成
- 编造 Agent 工作经验(背调会查)
- 夸大项目规模与效果
- 把"看过论文"说成"实现过"

**面试官会重点追问,编造的东西一问就露。**

```
- 消息队列 Kafka 经验,适用于 Agent 异步通信

技术技能
```

### Q4: 面试前的准备清单有哪些? 技术复习、项目梳理、公司调研、模拟面试分别怎么做?

<details>
<summary>查看答案</summary>

#### 一、面试前准备的总框架

```
面试前准备(建议面试前 1-2 周开始)
├── T-14d: 技术复习(31 天知识图谱过一遍)
├── T-10d: 项目梳理(每个项目 3 层深度)
├── T-7d:  公司调研(业务/技术栈/团队)
├── T-5d:  模拟面试(至少 3 轮)
├── T-3d:  高频题突击(对应公司面经)
```

#### 三、项目梳理:3 层深度法

每个项目准备 3 层,面试官问到哪层都能接住:

```
将一次解决率从 62% 提升至 84%。"
```

##### L2:技术架构 + 关键决策(3-5 分钟)

```
要点:
1. 整体架构图(能在白板画出来)
2. 关键技术选型 + 为什么这么选
3. 你做的核心模块的技术细节
4. 遇到的技术挑战 + 怎么解决

示例(架构):
用户 → API 网关 → Agent 编排层(LangGraph 状态机)
                          ↓
              ┌───────────┼───────────┐
              ↓           ↓           ↓
          RAG 召回    Tool Call    Memory
          (BM25+Emb   (12个工具)   (短期+长期)
           +Rerank)
              ↓
          LLM(Qwen2.5-72B, vLLM 部署)
              ↓
          响应生成

关键决策:
- 为什么选 LangGraph 不选 LangChain? → 状态机更适合多轮对话
- 为什么选 Qwen 不选 GPT? → 数据合规 + 成本
- 为什么 BM25+Embedding 混合? → 短文本 BM25 强,长文本 Embedding 强
```

##### L3:踩坑 + 优化 + 量化(深挖层)

```
要点:
1. 踩过的坑(至少 3 个,具体到代码层面)
2. 优化过程(从 V1 到 V2 怎么改进)
3. 量化指标怎么算出来的
4. 如果重做会怎么改

示例踩坑:
"RAG 召回初期准确率只有 70%,排查发现:
1. Embedding 模型用通用模型,领域词召回差
   → 用领域数据微调 Embedding,准确率 +8pp
2. Chunk 策略是固定 512 token,跨段落信息丢失
   → 改为语义切分 + 重叠窗口,+5pp
3. Rerank 模型缺失,Top-K 里噪声多
   → 加 BGE-Reranker,Top-3 命中率 +6pp
最终 89%。"
```

### Q5: 面试中的表达技巧有哪些? 如何结构化表达? 如何展示技术深度? 遇到不会的问题怎么办?

<details>
<summary>查看答案</summary>

#### 一、结构化表达:两个黄金模型

##### 模型 1:总-分-总(万能框架)

```
总: 一句话给出结论 / 方向
分: 2-3 个支撑点(技术细节 / 案例 / 对比)
总: 总结 + 你的判断 / 取舍

示例(问: 你怎么做 RAG 召回优化的?)
"我用的是多路召回 + Rerank 的方案(总)。
具体分三路:
1. BM25 做关键词召回,适合短 query
2. Embedding 做语义召回,用微调过的 BGE 模型
3. Rerank 用 Cross-encoder 重排 Top-50 → Top-5
另外做了 Query 改写和 HyDE(分)。
最终召回准确率从 62% 提升到 89%(总)。
如果重做,我会再加上知识图谱辅助召回。"
```

##### 模型 2:PREP(适合观点类问题)

```
P (Point): 观点
R (Reason): 原因
E (Example): 例子
P (Point): 重申观点

示例(问: 你觉得 LangChain 还是 LlamaIndex 好?)
"P: 我认为看场景,RAG 重的话 LlamaIndex 更合适。
R: 因为 LlamaIndex 在索引、检索、Rerank 上抽象更细致。
E: 我之前做客服 RAG,用 LlamaIndex 的 Hybrid Retriever
   比自己拼 LangChain 的 Retriever 少 30% 代码。
P: 所以 RAG 场景我倾向 LlamaIndex,
   但复杂 Agent 编排我还是选 LangGraph。"
```

#### 二、技术深度展示:主动深挖

面试官最怕"浮在表面"。你要主动往深处走:

##### 技巧 1:讲完方案主动讲取舍

```
"我选了 A 方案,但也考虑过 B 和 C:
- A: XX 优点,XX 缺点
- B: XX 优点,XX 缺点
- C: XX 优点,XX 缺点
最终选 A 是因为 XX 约束(成本/工期/团队能力)。"
```

##### 技巧 2:讲完实现主动讲边界

```
"这个方案在 XX 场景下有效,
但有几个边界问题:
1. 上下文超过 XX token 时性能下降
2. 工具数量超过 XX 时选择准确率降低
3. 多轮对话超过 XX 轮时记忆丢失
对应的缓解方案是 XX。"
```

##### 技巧 3:讲完结果主动讲改进

```
"最终结果是 XX,但还有改进空间:
1. 如果重做,我会用 XX 替代 XX
2. 下一步计划加 XX 模块
3. 业界最新论文 XX 提出了 XX 思路,值得借鉴。"
```

#### 三、遇到不会的问题:3 步应对法

**绝对不能:**
- 直接说"不知道"然后沉默
- 瞎编(面试官一追问就露馅)
- 反问"你觉得呢"

**正确做法:**

```
Step 1: 诚实承认 + 定位已知部分
"这个具体我没做过,但我理解它和 XX 相关。"

Step 2: 关联已知知识 + 给出思考路径
"如果让我做,我会从这几个角度思考:
1. 先明确 XX 约束
2. 参考 XX 方案
3. 用 XX 评估
不确定的地方是 XX。"

Step 3: 主动请教 + 表达学习意愿
"这块我确实不熟,您能分享下你们的做法吗?"
(面试官会觉得你诚实 + 有思考能力)
```

**示例(问: 你做过 RLHF 吗?)**

```
"RLHF 我没在生产环境做过完整流程(诚实),
但我理解它的核心是 SFT + RM + PPO 三阶段(已知)。
我做过 SFT,用 LoRA 微调 Qwen,
RM 我读过 InstructGPT 论文,理解 reward 建模思路,
PPO 部分我不熟,但理解它是策略优化算法(关联)。
如果让我做,我会先复现trl库的示例,
再在小数据上跑通,最后扩展(思考路径)。
你们团队的 RLHF 是怎么落地的?(请教)"
```

#### 四、反问环节:准备 3 个好问题

**好问题示例:**

| 类别 | 问题 |
|------|------|
| 技术栈 | "团队目前 LLM 推理用的是什么方案?有自建还是用 API?" |

**不要问:**
- 加班多不多(显得不努力)

- "我表现怎么样"(让面试官尴尬)

#### 五、编程/系统设计题:先澄清再动手

```

4. 逐个组件深入设计
5. 讲瓶颈与扩展方案
6. 讲监控与容灾
```

### Q6: 面试中的薪资谈判怎么做? 如何谈薪? 多个 offer 如何比较?

<details>
<summary>查看答案</summary>

#### 一、谈薪的核心原则

```
1. 不要先报数(让对方先开)
2. 不要只看月薪(看总包)
3. 不要急于接受(给自己 3-7 天考虑)
4. 不要威胁(用"另一个 offer"做杠杆要诚实)
5. 不要只谈钱(WLB/成长/期权都要谈)
```

#### 二、谈薪时机

| 阶段 | 是否谈薪 | 注意 |
|------|---------|------|
| 简历投递时 | 不主动谈 | 期望薪资栏可写"面议" |
| 一面/二面(技术面) | 不谈 | 聚焦技术 |
| HR 面 | 初步沟通 | 给区间,不报死数 |
| 拿到 offer 时 | 正式谈 | 这是最佳时机 |

#### 三、谈薪话术模板

##### 场景 1:HR 问期望薪资

```
错误:"我希望 50k×16"(先报数,被锚定)
错误:"越多越好"(显得没准备)

正确:
"我了解了一下市场行情,结合我的经验,
期望总包在 XX-XX 万之间(给区间,下限是你目标)。
当然,具体的包我也看重团队和成长空间,
如果其他方面有亮点,薪资可以再聊。"
```

##### 场景 2:HR 报了一个低于预期的数

```
错误:"太低了,我不接受"
错误:"行吧"(直接接受)

正确:
"感谢这个 offer,我对贵司也很感兴趣。
不过这个数距离我的预期有些差距,
我目前手上有另一个 offer 在 XX(高出 20%),
但说实话我更倾向你们 team。
能不能在总包上再聊聊?
比如 base 调到 XX,或者 sign-on 加 XX?
我觉得这样我能更安心加入。"
```

##### 场景 3:HR 说"我们已经到顶了"

```
"理解,那我能不能问下:
1. 有没有 sign-on bonus?
2. 期权/股票能不能多给一些?
3. 半年后调薪的机制是怎样的?
4. 是否有绩效奖金?
如果薪资确实没空间,这些方面能不能补充?"
```

##### 场景 4:多个 offer 杠杆

```
"实话跟您说,我现在有 A 公司的 offer,总包 XX。
但我的首选其实是你们,因为 XX(业务/团队/技术)。
如果你们能 match 或接近 A 的水平,
我今天就拒掉 A,签你们。"

注意:
- 必须真有 offer,不能编
- 表达诚意,不威胁
- 给明确决策时间
```

#### 四、offer 比较的 5 维度

| 维度 | 权重参考 | 评估要点 |
|------|---------|---------|
| 总包 | 30% | base×月数 + sign-on + 期权 + 奖金 |

**打分模板:**

| offer | 总包 | 成长 | 业务 | WLB | 风险 | 总分 |
|------|------|------|------|-----|------|------|

**不要只看钱。** 一个 100w 但天天加班没成长的 offer,不如 80w 但能学到核心技术的 offer。

### Q10: 面试后的 follow-up 和复盘怎么做? 感谢信、复盘记录、未通过如何应对?

<details>
<summary>查看答案</summary>

#### 一、面试后 24 小时内:感谢信

##### 为什么要发感谢信

- 显示专业素养
- 加深面试官印象
- 补充面试中没答好的点

##### 感谢信模板

```
主题: 感谢 XX 岗位面试机会 - [你的名字]

XX 老师您好,

感谢您今天抽出时间面试我。

和您聊到 [具体话题,如"你们的 Multi-Agent 架构"] 让我收获很大,
更加坚定了我想加入贵司的决心。

面试中您问到 [没答好的问题],
我事后想了一下,补充一下我的理解:
[简短补充,2-3 句]

期待后续的好消息,也欢迎随时进一步沟通。

祝好,
[你的名字]
[联系方式]
```

##### 注意事项

- 24 小时内发,越快越好
- 简短(不超过 200 字)
- 提一个面试中的具体话题,显得真诚
- 不要群发,要个性化
- 不是所有公司都吃这一套(大厂面试官可能收不到),但发了没坏处

#### 二、面试后 48 小时内:复盘记录

##### 复盘模板

```
面试复盘 - [公司名] [岗位] [日期]

1. 基本信息
   - 公司: XXX
   - 岗位: Agent 工程师
   - 面试官: XX(技术背景/风格)
   - 时长: 60 分钟
   - 轮次: 二面

2. 题目记录
   | 题目 | 我的回答 | 评价 | 改进 |
   |------|---------|------|------|
   | RAG 召回怎么优化? | 多路+Rerank | 良好 | 可加 HyDE |
   | vLLM 原理? | PagedAttention | 一般 | 需补 KV Cache 细节 |
   | Multi-Agent 通信? | Redis Stream | 良好 | 可加对比 Kafka |

3. 表现评估
   - 技术深度: 4/5
   - 表达清晰: 3/5(有点紧张,口头禅多)
   - 项目讲解: 4/5
   - 反问环节: 2/5(没准备充分)

4. 经验总结
   - 做得好的: XX
   - 做得差的: XX
   - 下次改进: XX

5. 待补知识
   - [ ] vLLM KV Cache 细节
   - [ ] Agent 评估指标体系
   - [ ] XX 论文复现
```

##### 复盘的价值

- 同类题目不再翻车
- 发现知识盲区,针对性补
- 优化表达,下次更流畅
- 积累面经,可分享/反哺他人

#### 三、未通过如何应对

##### 心态调整

```
1. 不要自我否定
   - 面试是双向选择,没过不代表你不行
   - 可能是岗位不匹配,不是能力问题
   - 可能是 HC 问题,不是你的问题

2. 不要气馁
   - 平均要投 20-50 份简历,面 5-10 家,拿 2-3 个 offer
   - 一次失败很正常

3. 不要抱怨
   - 不要在网上吐槽面试官
   - 不要在脉脉黑公司
   - 行业很小,留好印象
```

##### 分析原因

| 原因 | 表现 | 应对 |
|------|------|------|
| 技术深度不够 | 追问到细节就卡壳 | 针对性补知识 |
| 表达不清 | 知道但讲不出来 | 多模拟,练表达 |
| 项目不匹配 | 项目与岗位无关 | 调整简历,投匹配岗位 |

| 文化不匹配 | 风格与团队不合 | 换公司 |
| HC 问题 | 岗位冻结 | 不是你的问题 |
| 薪资预期高 | 超出预算 | 调整预期或换公司 |

##### 持续投递策略

```

2. 按优先级排序
   - 梦想公司 → 重点准备
   - 备选公司 → 用来练手
```

## 易错点提醒(10 个)

### 1. 简历只写"做了什么"不写"达成了什么"

**错误:** "负责 RAG 系统开发"
**正确:** "设计 RAG 召回架构,准确率从 62% 提升至 89%"
**原因:** 面试官看简历 30 秒,没数字 = 没能力证明。

### 2. 量化数字离谱

**错误:** "召回准确率提升 80pp"(从 60% 到 140%?)
**正确:** "召回准确率提升 27pp"(62% → 89%)
**原因:** 面试官心里有数,太离谱反而扣分 + 追问会露馅。

### 3. 简历堆砌技术名词无细节

**错误:** "熟悉 LangChain、LlamaIndex、AutoGen、vLLM、RAG、Multi-Agent"
**正确:** 在项目里具体写"基于 LangGraph 实现状态机式 Agent,支持 12 个工具"
**原因:** 技能栏堆砌 = 注水,项目里有细节 = 真懂。

### 4. 转岗简历编造 Agent 经验

**错误:** 把团队项目说成自己独立完成,或编造没做过的项目
**正确:** 突出可迁移经验 + 自驱项目 + 开源贡献
**原因:** 背调会查 + 面试追问会露馅 + 诚信比能力重要。

### 5. 面试中直接说"不知道"然后沉默

**错误:** "这个我不知道。"然后等下一题
**正确:** "没做过,但和 XX 相关,如果让我做,我会 XX。"
**原因:** 面试官考察的不是知识储备,是思考能力。

### 6. 面试中抢话/打断面试官

**错误:** 面试官还没问完就抢答
**正确:** 听完整,停顿 1-2 秒,再回答
**原因:** 显得不尊重人 + 容易答错(没听清问题)。

### 7. 谈薪先报数

**错误:** HR 还没问,自己先说"我期望 50k×16"
**正确:** 让 HR 先开,你再说"结合市场,期望总包 XX-XX 万"
**原因:** 先报数被锚定在低位,你值 60w 但报了 40w,HR 不会主动加。

### 8. 只看月薪不看总包

**错误:** "A 给 45k,B 给 50k,选 B"
**正确:** 算总包:A 是 45k×16=72w,B 是 50k×13=65w,选 A
**原因:** 月薪 × 月数 + sign-on + 期权 + 奖金 才是真总包。

### 9. 接受口头 offer

**错误:** HR 口头说"给你 50w",你直接提离职
**正确:** 等书面 offer 到手再提离职
**原因:** 口头 offer 反悔你无证据,可能赔了夫人又折兵。

### 10. 面试未通过就自我否定

**错误:** "我太菜了,Agent 不适合我"
**正确:** "这次没过,原因是 XX,下次改进 XX"
**原因:** 面试是双向选择,没过 ≠ 不行,可能是匹配度问题。平均要面 5-10 家才有合适 offer。
